# 栖作使用指南

[返回 README](../../README.md)

## 初次启动

1. 按 README 安装开发环境并启动。当前公开版不附带模型或预配置的私人账号。
2. 打开「设置 → 账号与连接」，配置提供商；在「模型与思考」选择默认模型。不同服务的认证、API 类型与模型名称可能不同，使用自己账号实际支持的选项。
3. 创建角色，或先用内置任务助手。测试模型连接成功后，再加入复杂插件。
4. 用独立测试目录完成一个小任务，核对文件和运行结果。

## 一个角色怎样配置

名称便于识别；简介要准确说明擅长的事；提示词描述方法、职责、交付和验证，不要只写“你是顶级专家”。角色可绑定已安装的技能与插件，设置推荐模型及思考强度；资源是否能执行仍受其运行环境与权限限制。

可以克隆已有角色，选择是否带上记忆，再调整定位。系统任务助手不能直接修改核心简介和提示词或删除，可克隆为自定义角色。归档角色不再作为新任务的正常选择。

修改角色卡不会偷偷重写正在运行的任务。工作台出现配置已变更提示时，查看「配置与交接」中的差异、职责和文件范围，再决定继续沿用还是完成交接。

## 单角色对话

1. 点击「对话 → ＋」，选择角色。
2. 工作涉及现有项目时选择项目文件夹；无项目时使用个人工作区。
3. 模型选“自动”可沿用角色推荐配置；具体模型及强度可手动选择。
4. 通过「文件」导入资料或图片。图片格式可上传不等于当前模型一定能理解图片。
5. 输入明确目标，例如“检查项目启动失败的原因，先复现，再做最小修复，说明验证结果”。
6. 遇到审批时阅读操作说明，必要时展开原始详情；工具失败、等待用户与模型输出中是不同状态。

完成后的思考默认折叠。可在相应回复下复制、创建分支或转入工作台；引用其他会话时，只把与任务相关的内容带入，不应把原会话中的历史命令当作新指令。

输入区下方显示当前角色的上下文和缓存数据。缓存来自供应商最近请求的回执；未知显示“—”。同一角色不同执行阶段的统计不应混在一起理解。缓存受供应商、工具与上下文排列影响，不保证固定命中率。

未发送的文字与附件按本机草稿保存。关闭重启后继续填写；这不代表尚未发送的内容已经进入模型上下文。

## 多角色工作台：从目标到交付

### 建立任务

创建任务，选择项目与角色；不清楚角色组合时先描述目标，让任务助手推荐。一个任务最多 8 个专业角色。建议从 2–4 个职责清晰的角色开始。

好的需求包括：目标用户、最终产物、已有资料、不能改的范围、运行环境与怎样算可用。不要只要求“做得高级”而不给交付标准。

### 理解四个视图

| 视图 | 用途 |
| --- | --- |
| 协作对话 | 查看你的要求、任务助手答复、分工回执与公开协作消息 |
| 成果 | 按角色查看真实文件、变更、冲突和应用结果 |
| 共同约定 | 核对共享接口、格式、版本及变更方案 |
| 执行记录 | 查看专业角色的具体执行、工具操作、等待原因与权限审批 |

角色的私有执行内容保留在其执行记录；共享消息不自动复制私有提示词、长期记忆或整段执行回复。共享交付文件本身仍可能包含用户要求共享的项目资料，发布前应自行审阅。

### 处理依赖和变更

先约定哪些角色依赖哪些文件。上游没有交付有效文件时，下游等待；上游改变交付或共同约定时，相关角色需要同步检查。任务助手负责判断和安排，内核核对归属、状态、版本与文件约束，不为每个项目写一套新的调度程序。

提出修改时继续在同一输入框说明。默认发送给任务助手，也可以选择具体角色；关闭某个角色的开关可暂停其参与。涉及接口冲突时先选择方案，不要让两个角色各自覆盖对方工作。

### 审阅和验收

打开「成果」，选择角色与文件：

- Markdown、代码和结构化数据可以阅读实际内容并查看变更。
- 静态网站可在浏览器打开本机预览；动态服务需要按项目说明运行，且须授权。
- 图片、SVG 图表、PDF、视频和音频使用对应查看/播放入口。
- Office 等文档通过 macOS Quick Look 处理；系统不支持的格式可下载或在访达中打开。

确认文件范围和冲突后应用到项目，再完成需要的构建、测试或联调。交付结构校验只能确认部分机械约束，不能证明视觉、业务、事实或安全正确。角色结束和整体验收通过是两回事。

### 中断后继续

先看当前状态、已有成果和执行记录，再选择继续；不应要求角色重做所有已完成操作。重启恢复不自动重放外部副作用。若文件在任务外被人工修改，需重新核对冲突与版本。

## 角色长期记忆

在「记忆」选择角色，只管理该角色的长期记录。支持手动创建、编辑纠错、版本记录、忘记和按状态筛选。对话时可以说“请记住：这个项目的前端交付要检查移动端和键盘焦点”。

自动记忆需要在外观与偏好中开启；模型决定是否提取适合复用的经验。建议定期检查记录的适用范围与来源，不把一次失败的推测保存成长期事实。工作台候选记忆应先核对来源与采纳状态。

## 时间记忆

在角色记忆页切换「时间记忆 → 新增时间记忆」，填写行动、工作项目和重复规则：

| 规则 | 填写内容 |
| --- | --- |
| 单次 | 具体日期与时间 |
| 每天 | 24 小时制时刻 |
| 每周 | 星期与时刻 |

也可在单角色对话中明确要求“每周一 09:30 检查这个项目的构建结果”，并核对软件创建的时间记录。自然语言不明确时，应补充时间、时区、行动和项目，不靠猜测授权。

应用运行时到点创建角色任务；关闭应用期间错过的行动只提示，由用户决定是否补执行。同一计划未结束不叠加执行。停用只影响后续触发，正在执行的任务需在对应会话停止。

## 技能、插件与认证

到「Skill 与插件」浏览来源、安装资源、查看已安装项并绑定角色。Pi 包、Claude 插件/技能与远程 MCP 的结构和环境要求不同，不承诺所有市场项目都兼容。

需认证的工具先检查可复用凭据，再验证实际访问权限；缺失时使用该集成支持的浏览器登录或配置流程。浏览器显示成功后，也应核对软件内的账号与工具状态。

工作台执行使用受控工具，不直接继承普通对话里所有扩展。命令、网络、远程服务器访问和操作审批分别核对；资源被占用时可能进入排队。

## 审批怎么选

工作台「角色权限」按角色配置，每次询问、自动询问或完全允许。自动询问仅对可识别的低风险只读操作放行，修改、删除与不确定操作仍确认。完全允许也不能越过职责范围、未授予能力与角色归属检查。

普通对话的权限模式在其输入区和设置中调整。应用层隔离不能代替系统级沙箱，尤其不要将任意 shell 命令或不可信插件视为天然安全。

电脑控制插件需要 macOS 屏幕录制和辅助功能权限；授予对象应以插件驱动实际使用的进程为准。没有权限时，模型本身无法绕过系统限制。

## 常见问题

**启动出现 SQLite / NODE_MODULE_VERSION 错误？**
退出正在运行的桌面进程，执行 `pnpm --filter @pi-harness/desktop rebuild:electron` 后再启动。运行 Node 测试时用 `rebuild:node`，完成后切回 Electron ABI。

**等待模型很久？**
查看当前处于准备工具、模型请求、审批、上游等待还是压缩状态。接口网络、提供商负载、模型思考强度、工具返回大小与上下文长度都会影响耗时；降低无关工具与上下文不等于保证提供商低延迟。

**缓存显示“—”？**
没有最近请求的有效回执，或供应商没有返回缓存字段；不是程序测得 0%。

**看不到网页效果？**
确认选中实际入口文件并点击预览。静态快照不会替你启动数据库或后端服务；动态项目需按其运行说明执行。

**角色等待批准或上游？**
查看该角色执行记录、权限入口与上游成果。检查实际等待原因后再继续，避免重复发送同一大段任务。

**时间任务未执行？**
核对角色、启用状态、时区、下次执行时间、应用是否在运行，以及前一次是否仍未结束。错过的任务不会擅自补跑。

**数据在哪里？**
在「设置 → 数据与备份」管理。为了兼容 Pi Harness 历史版本，资料目录可能沿用旧内部名称；不要为更名手动搬动或删除。凭证与私人数据不能随源码提交。
