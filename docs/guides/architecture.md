# 架构与能力边界

[返回 README](../../README.md)

## 组成

Electron 主进程负责窗口、凭证适配、生命周期与 IPC；React 渲染进程负责三栏界面；contracts 用 TypeBox 约束通信；runtime 负责角色、记忆、任务与工作台。SQLite 记录持久状态，pi SDK 负责模型会话和工具执行适配。

## 模型判断与内核约束

模型理解需求、推荐角色、提出分工、执行专业工作和判断内容是否满足目标。内核处理可机械验证的事实：角色是否存在/加入/暂停、职责路径、授权、依赖、输入输出版本、任务去重、写入冲突和状态持久化。

分工、角色规划与交付使用结构化提交和校验，避免只从自由文本中猜测工作状态；可修复的格式错误回馈给模型。Schema 保证部分数据结构，不保证任务判断或产品正确，也不需要为每个项目重写内核。

## 角色隔离

- 专业执行使用角色自己的配置快照、相关记忆与任务会话。
- 公开协作规划使用公开角色名称/简介、需求、职责和共同约定，不读取全部私有提示词与记忆。
- 共享执行回执来自受控交付信息，不直接复制私有执行回复。
- 文件在角色工作副本中修改，应用前检查路径与版本；依赖交付确认后下游才使用。
- 命令、网络与插件有能力配置和审批；独占工具通过资源队列使用。

这些措施是应用层隔离，不是操作系统虚拟化。第三方插件、shell 或文件内容仍需要信任判断。不能宣称任意插件都不会绕过本机资源边界。

## 稳定性

请求、角色执行、交付、审阅与应用分别记录；中断/重启恢复基于已有状态，不盲目重播所有副作用。等待批准、等待上游、资源排队与模型响应有独立展示。任务完成还需要查看真实成果与验收依据。

长期记忆按角色归属检索并记录来源、适用范围和版本；时间记忆有持久化计划和执行会话，同计划不重入，错过时间只提示。

## 上下文与用量

上下文管理关注当前模型容量、相关记忆、历史内容和工具结果大小，必要时压缩并展示状态。缓存是提供商行为；软件展示回执，不声称能强制命中。逐轮用量和响应耗时用于定位阶段，不等于服务端完整性能数据。

## 当前限制

- 主要验证平台为 macOS arm64；其他平台不提供同等保证。
- 没有内置模型、媒体模型或云端多人协作服务。
- 工作台受控执行与普通对话的扩展加载不同，不能把“已绑定”当作“任何环境都可用”。
- 静态网页预览不自动启动动态后端；Quick Look 取决于 macOS 格式支持。
- 时间任务需要应用运行，不是独立系统后台调度服务。
- 模型可能误判、工具可能失败、Schema 不能验证所有语义；交付必须审阅。
